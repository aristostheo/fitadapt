# Entry-By-Entry Personalized Planning

`personalized_planning_v1` builds a transparent proposed calorie and macro plan from the complete
history supplied by the caller. It is stateless: no observation, plan, preference, or target is
stored. A plan is decision support, never an automatically applied prescription.

## Construction

For every snapshot, FitAdapt composes existing public policies rather than introducing another
energy, smoothing, lifecycle, recommendation, or macro formula:

```text
UserProfile + observation prefix + NutritionPreferences
    -> baseline calorie target
    -> lifecycle status and adaptive-TDEE evidence
    -> existing calorie recommendation
    -> selected calorie basis
    -> existing preference-driven macro allocation
    -> target envelope around the exact selected plan
```

`NutritionPreferences` stays user-selected. FitAdapt does not infer a dietary strategy. Macro grams
can change when the selected calorie target changes, but the strategy itself is not learned.

## Calorie Basis

| Lifecycle stage | Selected target | Macro calorie source |
| --- | --- | --- |
| `baseline` | Existing baseline calorie target. | `baseline` |
| `calibrating` | Existing baseline calorie target. | `baseline` |
| `early_personalized` | Existing baseline calorie target; no premature adaptive target is invented. | `baseline` |
| `personalized` with an actionable recommendation | Exact existing `proposed_intake_target_kcal_per_day`. | `personalized` |
| `personalized` with no safe/actionable recommendation | Existing baseline calorie target, with the recommendation reasons retained. | `baseline` |

The existing recommendation engine supplies its own hold threshold, maximum adjustment cap, and
safety gates. Planning does not reimplement them. A fallback never forces a non-positive or
macro-infeasible personalized target; if the caller's selected macro strategy itself cannot fit a
selected target, the existing macro-policy error remains explicit.

Every current and progression snapshot exposes `target_envelope`. It preserves the same selected
target, calorie source, strategy, and exact macro plan, then adds the versioned V1 flexibility bands
documented in [nutrition target ranges](nutrition-target-ranges.md). Baseline, calibrating, and
early-personalized snapshots therefore retain baseline-source envelopes. Actionable personalized
snapshots use the safe recommendation target; a safety fallback retains its baseline target and
recommendation reasons.

## Progression Semantics

`build_personalized_plan_progression` sorts submitted observations by date and returns exactly one
snapshot for each submitted observation. Snapshot `n` is built only from the first `n` chronological
observations. Missing calendar dates do not create synthetic snapshots. Duplicate dates propagate
the existing `TrendAnalysisError`.

The first snapshot has no previous target or change. Later snapshots record the exact previous
selected target and `current_selected_target - previous_selected_target`, without rounding. Adding
or changing a future entry cannot alter an earlier snapshot.

Every entry recomputes evidence, but it need not change calories. Calendar-aware trends, adaptive
median aggregation, and conservative recommendation hold/cap policy can correctly retain the same
proposal across multiple entries.

## Executable Example

The following deterministic progression is generated by the planning unit-test fixture: a
30-year-old, 80 kg moderately active male maintenance profile, balanced preference, 21 daily 2,400
kcal entries, and a linear -0.10 kg/day observed weight change.

| Date | Lifecycle stage | Calorie basis | Selected target (kcal/day) |
| --- | --- | --- | ---: |
| 2026-01-01 | `calibrating` | `baseline` | 2759.0 |
| 2026-01-11 | `early_personalized` | `baseline` | 2759.0 |
| 2026-01-21 | `personalized` | `personalized` | 2550.0 |

## Boundaries And Limitations

Lifecycle stage is readiness evidence, not confidence or clinical accuracy. Adaptive TDEE remains
sensitive to logged intake, scale noise, hydration, glycogen, and its existing assumptions. Planning
does not call synthetic ML, invent an early adaptive target, modify baseline calculations, alter
recommendation policy, or persist state. It also does not implement food selection,
allergies/restrictions, medical nutrition therapy, meal generation, micronutrient analysis,
training-day/rest-day targets, or budget, cuisine, cooking, or schedule optimization.
